# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Nuxt 4 dashboard app built on **Nuxt UI v4** (`@nuxt/ui`). A **Vertex Digital Marketing** product/inventory system, built by porting screens from a Claude Design project via the `DesignSync` MCP (see the `vertex-design-import` / `vertex-import-conventions` memories). The upstream Nuxt UI template pages/layout/components were deleted — only the Vertex screens remain. Package manager is **pnpm** (v11).

## Commands

```bash
pnpm dev        # dev server on http://localhost:3000
pnpm build      # production build
pnpm preview    # preview prod build
pnpm lint       # eslint (Nuxt config, stylistic: no comma-dangle, 1tbs)
pnpm typecheck  # vue-tsc via nuxt typecheck
pnpm vitest run # vitest — two projects: `unit` (node) and `nuxt` (@nuxt/test-utils)
```

`postinstall` runs `nuxt prepare` (regenerates `.nuxt/`, required before typecheck/lint work).

**Adding a file under `app/composables/` or `shared/utils/` needs a dev-server restart.** The auto-import manifest is built at startup, and neither typecheck nor vitest sees the stale one — they build their own module graph. The symptom is a runtime "X is not a function", sometimes only as a toast that has already expired by the time you look.

## Architecture

Nuxt 4 `app/` directory layout. Auto-imports are on — do not manually import Vue APIs, `~/types`, `app/utils/*`, or components; refer to components by PascalCased path (e.g. `app/components/vertex/Sidebar.vue` → `<VertexSidebar>`).

- **Layout shell**: [app/layouts/default.vue](app/layouts/default.vue) is the base shell — `<VertexSidebar>` (collapsible grouped nav) + a content `<slot>`, DM Sans font. Every page renders in it by default. `/` redirects to `/dashboard` (routeRules in [nuxt.config.ts](nuxt.config.ts)).
- **Screens**: ported from Claude Design `*.dc.html` sources. [app/pages/dashboard.vue](app/pages/dashboard.vue) is the reference (stats grid + product table with rule-based filters, chips, pagination). See the `vertex-import-conventions` memory before porting more.
- **Types**: domain types (`Category`, `Platform`, `ProductRow`, …) live in [shared/types/domain.ts](shared/types/domain.ts) so `server/api` shares one definition; the Vertex API's own documents are in [shared/types/vertex.ts](shared/types/vertex.ts) (what is left of our own wire contract, `FieldErrors`, is in [shared/types/api.ts](shared/types/api.ts)). [app/types/index.d.ts](app/types/index.d.ts) re-exports them and adds presentation-only shapes (`FilterRule`, `DashStat`, `CategoryTreeRow`, …). App code still imports everything via `~/types`. `shared/` cannot import from `app/` or `server/`, and cannot use Vue or Nuxt runtime APIs.
- **Data / stores**: no localStorage. Every resource reads and writes through its own binding in `app/composables/` — `useApiProducts()`, `useApiCategories()`, `useApiPlatforms()`, `useApiAttributes()`, `useApiFeeItems()` — each a thin call to [useVertexResource.ts](app/composables/useVertexResource.ts), which keeps the resource name and the envelope in one place. **Add a resource by writing its `useApiX.ts`, not by passing a new string.** Products are the exception: `useApiProducts()` has no `list()`, only `page()`, because the catalogue is unbounded — and it carries the pricing, variant, bundle and platform-content endpoints beside the resource itself. The pure helpers over an already-loaded list (`categoryById`, `attributeNames`, usage counts) stay sync in `app/utils/*.ts`; the pure halves of a whole screen live in `shared/utils/` (`product-detail.ts`, `product-create.ts`, `variant-pricing.ts`, `product-row.ts`) so they can be tested directly. The only browser storage left is the sidebar's collapsed flag and a `sessionStorage` toast hand-off.
- **Rendering**: SSR is on, but the screens were ported from a client-side design and all but one still fetch in `onMounted`, which only runs in the browser — so the server renders a skeleton it had everything it needed to fill. Every page is converted to `useAsyncData` now, forms included. Two rules the conversions turned up: **call `useAsyncData` BELOW the `useApiX()` bindings it uses**, or the awaited handler reads them in their temporal dead zone and SSR fails with `Cannot access 'xApi' before initialization`; and on a page whose mutations write the list back, use the returned `data` AS the list — it is a writable `Ref`, so `fees.value = [...]` keeps working untouched.
  - **Trap: the handler does not re-run on hydration.** Nuxt serialises `data` and replays it, so a handler that WRITES refs seeds them on the server and leaves the client holding empty ones. Return the documents and seed outside the handler, where it runs on both sides — `products/detail/[id].vue` is the worked example.
  - **Every binding fetches through [useApiFetch()](app/composables/useApiFetch.ts)**, never plain `$fetch`. On the server it is `useRequestFetch()`, which forwards the incoming cookie — without it an SSR fetch of `/api` is unauthenticated and 401s. On the client it reads `globalThis.$fetch` at CALL time, because `useRequestFetch()` there returns the `$fetch` captured before plugins ran, which is NOT the one `auth-401.client.ts` installs — using it would silently disable the session-expiry redirect.
  - **The auto-imported `$fetch` is not intercepted either.** It comes from `#build/fetch.mjs`, whose last line is `export const $fetch = globalThis.$fetch` — a snapshot taken at module evaluation, before plugins run. Measured in a page: `$fetch === globalThis.$fetch` is **false**. So anything that must notice a dead session reads `globalThis.$fetch` at call time or goes through `useApiFetch()`. The three remaining direct `$fetch` calls are deliberate: login and logout, where a 401 is the answer rather than a problem.
  - **Trap: `Date.now()` and other browser reads stay in `onMounted`.** Reading them during render makes the server HTML and the first client render disagree. `dashboard.vue`'s "New" badge is the example.
- **API layer**: `app → server/api → Vertex Commerce API`, described by [docs/api/vertex-commerce.postman_collection.json](docs/api/vertex-commerce.postman_collection.json). One seam, [server/utils/vertex.ts](server/utils/vertex.ts); handlers only call `vertex()`. Set `NUXT_VERTEX_API_BASE` **including the `/api/v1` prefix** (without it every path 404s) — copy `.env.example` to `.env`. The wire translation is pure and lives in [shared/utils/vertex-wire.ts](shared/utils/vertex-wire.ts) + [shared/utils/cursor.ts](shared/utils/cursor.ts), tested against the collection's own examples in `test/unit/`. Contract: `{data}` envelope, snake_case, **cursor pagination** (no page numbers — categories have none at all and return the whole tree), **PATCH** with a required `lock_version` (409 `stale_version`), integer JPY with no minor unit, localized fields as `{ en: … }` maps, errors as `{error:{code,message,details?}, errors?:{field:[{code,message}]}}`. See [server/README.md](server/README.md).
  - **Trap: the case mapper renames keys, not values.** A field name carried as a VALUE (`reset: ['is_enabled']`, `lockedFields`, `sort: '-updated_at'`, `stockStatus: 'out_of_stock'`) stays in the API's spelling — translate it explicitly.
  - **Trap: the Postman mock proves almost nothing.** It ignores request bodies and path ids, persists nothing, and answers some writes with a saved *error* example (403 on `POST /products`, 401 on `POST /price-plans`). A body with a wrong key name comes back 201. That is why every mapping is unit-tested against the collection's example bodies rather than checked in the browser.
  - **No invented data is rendered any more.** The counters come from `GET /admin/catalog/stats`, Version History from `GET /admin/audit-logs`, an unknown product id shows a not-found card, and the Dashboard fetches a row's variants with `?parentId=` when it is opened instead of turning `variantCount` into rows it made up. `shared/seeds/` went with them.
  - **Generating variants REPLACES the whole set** — a combination that drops out is deleted if it was never ordered and switched off if it was — so Product Detail asks `previewVariants` first and shows what would be created, removed, switched off and kept before writing anything. It refuses outright when a candidate's SKU belongs to another product, or when converting a simple product would strand live subscriptions or bundles (that needs `subscriptionTargetCombination`, which has no picker yet). Over 100 variants answers 202 with a `jobId` and nothing polls it, so the page says the work is running rather than showing a count that never arrives.
  - **A bundle's contents are a PUT that replaces everything.** Ids already in the bundle keep their in-bundle prices; anything sent without one is treated as new and the price set for it is gone — silently, with a 200. So `shared/utils/bundle-contents.ts` carries `id` from read to write, and Product Detail confirms before saving anything that drops a selection.
  - Saving a product is a **sequence**, and the first step commits: `POST /products` (always a Draft, no prices) → `POST /:id/price-plans` → `POST /:id/status`. A configurable parent is not sellable, so its prices go on its variants, which must be activated before it can be.
- **Auth**: `nuxt-auth-utils`. Every `/api` route needs a session; only `/api/auth/login`, `/api/_health` and the module's own `/api/_auth/session` are public (exact match, in [shared/utils/auth.ts](shared/utils/auth.ts)). **The upstream token never reaches the browser** — login puts it under the session's `secure` key, which the module strips before answering the client (`const { secure, ...data } = session`), and [server/utils/session.ts](server/utils/session.ts) is the only thing that reads it back. `vertex(event)` turns it into an Authorization header; `event` is a required parameter so no call site can fall back to a shared credential. Screens read `useAuth()` — a thin wrapper over `useUserSession()` adding `can(permission)` and a logout that also revokes upstream. [app/middleware/auth.global.ts](app/middleware/auth.global.ts) sends a signed-out visitor to `/login` carrying `?redirect=`, read back through `safeRedirect` so the form cannot be turned into an open redirect.
  - **The module's defaults are not enough**; [nuxt.config.ts](nuxt.config.ts) adds three, each checked against its source and h3's rather than assumed: `sessionHeader: false` (h3 otherwise accepts a sealed session in an `x-nuxt-session` header, and that header WINS over the cookie), `secure` outside dev only (WebKit will not store a Secure cookie on `http://localhost`), and a `maxAge` (without one the cookie dies with the browser session).
  - **Trap: not every 401 means the session is over.** Both halves — `vertex()` server-side and the plugin client-side — decide by `error.code` (`isSessionEnding`), never by status. Deciding by status logged people out whenever they saved a price, because the Postman mock answers that write with a saved 401 whose code is the literal string `"string"`.
  - **`permissions` is frozen at login** for the cookie's 7-day life: the session endpoint answers from the cookie rather than re-asking the API. Harmless while `can()` gates nothing on screen — whoever adds gating has to decide whether to re-read instead.
  - **Trap: `navigateTo` does nothing inside a `$fetch` interceptor**, and neither does navigating away without first clearing the session state. It needs a Nuxt context and fails silently without one, so [app/plugins/auth-401.client.ts](app/plugins/auth-401.client.ts) uses the captured router — and writes `useUserSession().session.value = null` **synchronously** first, because otherwise the route middleware still sees `loggedIn`, takes its "already signed in" branch and bounces straight back to the page just left.

## Conventions

- Theme colors set in [app/app.config.ts](app/app.config.ts) (`primary: green`, `neutral: zinc`); the green palette is redefined as CSS vars in [app/assets/css/main.css](app/assets/css/main.css). Change brand color in both.
- Icons: `i-lucide-*` (Lucide) and `i-simple-icons-*` (brands), resolved by Iconify at build.
- Forms/validation: **zod v4** + Nuxt UI `UForm` / `UFormField`. Every control is a Nuxt UI component — `UInput` / `UTextarea` / `USelect` / `USwitch` — themed in [app/app.config.ts](app/app.config.ts) and sized by the presets in [app/utils/field.ts](app/utils/field.ts) (`fieldCompact` / `fieldCompactSm` on the two product forms, `fieldUi` elsewhere, `SELECT_FILTER` on the dashboard, `SELECT_ADD_VALUE` for the "+ Add value" pickers). There is no `.field-input` any more.
- `USelect` traps: Reka rejects `''` as an item value (it reserves `''` for "cleared"), so a real "all" choice needs a sentinel mapped back to `''` (see `ALL` in [app/pages/dashboard.vue](app/pages/dashboard.vue)) and a blank prompt becomes the `placeholder` prop. A menu-style picker that must not keep its value binds `null` (`NO_VALUE`), not `undefined` — `undefined` makes Reka go uncontrolled and the pick sticks on the trigger.
- Two UInput traps: `@focus` is dropped (not an emit, and overridden internally) — use `@focusin`; and an absolutely-positioned prefix like the `¥` span needs `z-10`, because UInput's root is positioned and paints over it.
- Toggles are `USwitch`, sized in [app/app.config.ts](app/app.config.ts) (`md` 40x22, `sm` 38x22, `xl` 44x24). Bind the value only — `v-model`, or `:model-value` + `@update:model-value`; adding `@click` as well flips it twice. Its root is a block-level flex container, so add `class="inline-flex"` when the parent is `text-center` or a non-flex block, else the row loses ~5px and centring breaks.
- A native `<button>` inside a `UForm` needs `type="button"` — it defaults to submit.
- ESLint stylistic rules are enforced: **no comma dangle**, 1tbs brace style, max 3 attributes per line on single-line templates. Run `pnpm lint` before finishing.
